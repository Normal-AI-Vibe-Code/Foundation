# CLAUDE.md — Foundation

You're working on Foundation, the company brain of Form Industries: a shared grid for people, apps and agents. Josh directs.

Every session:
1. Read `SPEC.md` (status, hookups, known issues) and `DESIGN.md` (the visual contract). The plan is a kanban: `docs/plan.json`, mirrored to GitHub issues and shown in the app under Settings → Plan.
2. `npm install && npm test && npm run typecheck`. A red build is the session.
3. Take the top card in **Next** on the plan board (or a §7 issue that's worse); move it to Doing, then Review or Done when it's checked (`docs/plan.json`, then `npm run plan:push`).
4. UI: on tokens only (`packages/ui/src/tokens.css`), shown on `#/design` first, checked in day and night.
5. Verify in the browser (`npm run dev`, http://localhost:1430; `?rafshim` for hidden/headless panes) and capture evidence in `docs/evidence/<date>_<slice>/`. `npm run e2e -w @foundation/client` runs the real-browser checks (two people, sections moved and split, voice, layouts, the perf trace) on its own server and data. `PERF_GPU=1 … -- frames` holds every surface to 60 fps on this machine's GPU (add `E2E_BUILD=1` for the production build).
6. Update SPEC §3 status and §7 honestly, and the card's column on the board. Commit with what changed and how it was checked.

Invariants (tested in `apps/server/test`): one board schema (`packages/protocol`); writes name their board; `request_id` idempotency; deletes need `confirm`; uploaded files are archived, never deleted; session tokens are stored hashed and never travel in URLs; nothing that spends money or runs third-party code starts without a person; viewers can't write a board (socket, tools or HTTP); what an agent is and which credentials its run uses are the server's to say, from the seat (never the request); an agent's script (`run_code`) runs only in the isolate and reaches only the same gated tools; a stored model key is sealed, never returned or logged; an agent's reasoning is not shared with a grid once its run has read anything beyond that grid.

ChatForm's invariants (tested in `apps/server/test/chat*.test.ts`): who wrote a message is the session's to say (a person's own session is that person, anything else is an agent, and no request names its author); a DM, a private channel, a portal and their huddles, files, transcripts and events reach only their members, admins included; chat writes carry `request_id`, removing a message needs `confirm` and keeps the row, uploads are archived; nothing leaves Foundation without a person (an agent's message in a bridged portal is a draft until a person in it sends it, and paid sends such as templates are never made); a bridge's webhook is authenticated by the service's signature on the raw body, and its credentials are never stored in plain text, returned or logged; an agent's turn in chat starts only from a person's own message (never from an agent's, a ghost's, a bridged or a brought-in one); a huddle seats people only, and agents are seated by a person; link previews and bridge downloads never fetch private, loopback or link-local addresses; replay never writes a board (a take is read-only, kept with its session and never deleted, and shown only to those who can see both the session and the grid); attaching from Vision reads only the configured Archive address; a Slack channel is bridged only once an admin links it (never a DM), a mirrored message never goes back out or starts an agent, and a bridge key pasted in a wizard is sealed, shown as set or missing (its last four characters at most) and audited by name only.

The network's invariants (tested in `apps/server/test/network.test.ts`): a server listens beyond loopback only by an admin's own press at its computer (or the environment), and answers only to its own LAN names while it does; an invitation is random, hashed, single-use, 15 minutes, bound to an allow-listed non-admin email, redeemed by POST only from another private-network computer, rate-limited and audited; the host terminal and browser, Places, machines, jobs, T3's own agents, bridge credentials, apps, agent tokens, spending and the server's own settings answer only a request from the server's computer (no forwarded header is trusted); the built page is served only on network names, never outside its folder, and `/m/` never shares its origin. Which server is which, and the rack recipe: `docs/server.md`. The architecture is `docs/chatform.md`.
