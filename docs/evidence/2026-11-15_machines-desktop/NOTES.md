## What was wrong, found by reproducing it

1. **A click never gave the terminal the caret unless the card was drawn at exactly 100 %** (it almost never is: a section fits its cards). `panels/scaledMouse.ts` re-sends each mouse press with the pointer's place in xterm's own pixels; xterm took the caret on the re-sent press, then the real press, left to do what a press on plain page does, moved focus to the page. Seen in the browser as `focusin` on xterm's textarea followed at once by `focusout`. The real press is now spent.
2. **The app's shortcuts took the shell's keys.** Ctrl+W (close a space), Ctrl+U (upload), Ctrl+K and Ctrl+L (the command bar), Ctrl+F, Ctrl+J, Ctrl+I, Ctrl+1–9 and a single Esc were taken by the shell's key handler whatever had focus; the talk sheet caught letters. Both now stand down while a key's target is a machine's shell (`lib/keysHeld.ts`).
3. **On Kiri, Ctrl+C interrupted nothing.** Kiri 0.1.18 starts a machine's processes with SIGINT, SIGTERM and SIGCHLD blocked (`grep SigBlk /proc/self/status` in an exec: `0000000000014002`); bash and busybox ash pass the mask on, so `^C` printed and the program ran on. The card's shell now starts through perl or python3 with the mask cleared, where the image has one (Ubuntu and Debian always have perl). **Alpine has neither**, and nothing in its base image can clear a mask (su, setsid, nohup, timeout, env, xargs, find, awk, socat were tried), so there the terminal opens with a line saying so and what to install (`apk add perl`).
4. **On Kiri, an exec's stream never closes when the program exits** (measured: still open 6 s after `true` exited, with the engine reporting `Running: false`). `execOnce` waited for the stream, so `machine_run` would have held its agent for the command's whole time limit plus 5 s on Kiri (not timed end to end; inferred from the stream, and no longer the case). Half-closing our side, as `docker exec` does, makes Kiri drop the stream at once, mid-command. The engine is now also asked whether the exec still runs (`untilExecEnds` in `machines.ts`).

Items 3 and 4 are Kiri's to fix; worth reporting upstream (a plan card below).

### §4 The board tool surface: the Machines row gains

`desktop_screenshot` (the screen as a picture), `desktop_mouse` (move, click, double_click, right_click, middle_click, drag, scroll_up, scroll_down at a pixel), `desktop_type` (text; a newline is Enter, a tab is Tab), `desktop_key` (keys and chords, e.g. `ctrl+c`, `alt+F4`): only on a machine where a person pressed Let agents use this desktop. `machines` now also says whether a machine has a desktop, whether agents may use it, and its pipes (what feeds `in`, where `out` goes, the last value of each). `connect` wires a machine's `in`/`out` to an app's port, a note (`text`) or a table (`rows`, or a cell such as `B2`).

### §2 The board document

`MachineState` gains (all optional, no migration): `wantDesktop`, `desktop { state: installing | ready | error, detail, by, at, w, h }`, `agentsMay { by, at }`, `agentAsked { by, for, at }`, `agentActs[]` (the last five: `by`, `for`, `did`, `at`), `io { inPreview, inBytes, inAt, outPreview, outBytes, outAt, error }`. A `LinkDoc` end may name a note (port `text`) or a table (port `rows` or a cell) when the other end is a machine's `in` or `out`; the server reads and writes those ends (`machineio.ts`). New socket: `/machines/:board/:panel/vnc` (RFB bytes only; tickets as for the terminal). New table: `person_prefs (user_id, key, value, updated_at)`.

### §7 Known issues: add

- **Ctrl+C in an Alpine machine on Kiri does nothing.** Kiri 0.1.18 starts a machine's processes with SIGINT blocked; Foundation clears that through perl or python3, and Alpine's base image has neither. The terminal says so when it opens; `apk add perl` and reopening it fixes it. Ubuntu and Debian are fine. Not looked at: Fedora, Arch, Rocky, openSUSE (they need python3 or perl in the image). Kiri's to fix.
- **Kiri leaves an exec's stream open after the program exits.** Foundation now asks the engine whether the exec still runs (a request a few times a second at first, then every 700 ms, for as long as a command runs). Kiri's to fix.
- **In a browser tab, Ctrl+W, Ctrl+T and Ctrl+N are the browser's**, whatever has focus: no page can take them. In the terminal they reach the shell in the checks only because Playwright's keys don't pass through the browser's own shortcuts. **Not verified in the packaged desktop app** (WebView2 has no tabs, so they should reach the shell; nobody pressed them there). The Keyboard Lock API in full screen would give them to the shell in a browser; not done.
- **The desktop was not opened in the packaged desktop app.** `desktop.html` is in the build (`vite build` makes it) and the app's page policy allows the frame (`csp: null`), but it was only run from Vite's dev server.
- **Not tried on Docker, macOS or Linux hosts.** The desktop and pipes use only the Engine API calls the terminal already uses (exec, a hijacked stream), and the stand-in tests are Docker-shaped, but no real Docker ran them: this computer's Docker pipe is Kiri.
- **No live model has driven a desktop.** The checks drive the tools with an agent's token (REST and MCP) and with the crew's script runtime (a fixed playbook, no model). The API runtime's image block (`agent.ts`) is typed and unexercised; a subscription run goes through MCP, whose picture was checked at the door, not inside Claude Code.
- **The desktop is 1280×800, fixed**, with no clipboard between it and the board, no sound, and no browser inside it (Ubuntu's Firefox is a snap). It is ~250 packages (1 to 3 minutes on this connection, about 700 MB of the machine's disk) and its processes keep running in the machine until it stops (they start again when someone opens the Desktop view).
- **One desktop, shared.** A person and an agent can both act on it at once; nothing takes turns between them (agents take turns among themselves).
- **The leave agents have doesn't expire.** It lasts until someone presses Stop or the machine is removed, across the machine's stops and restarts.
- **A busy agent fills the activity.** Every action, a look included, is a line, and the board keeps the last 400.
- **Wires to and from notes and tables aren't drawn.** They carry values (the server reads and writes those ends) and are listed, made and removed on the machine's strip, but the wire layer draws card-to-card wires only. `in` takes one source (the first wire).
- **Pipes move only while watched**: the machine's card on someone's screen, or the machine wired and the board open somewhere. `in` is capped at 64 KB and `out` at 256 KB (the strip says so when cut). `out` is polled every 2 s (one exec each time).
- **A table cell wired in is the cell as typed** (a formula arrives as its text, not its value): the server doesn't compute tables.
- **Settings has no place for the `computer_use` preference yet** (`GET/POST /api/prefs` and `computerUseDefault` are there for it).

## Decisions the owner might want differently

- **The desktop is not a published port.** The brief suggested noVNC inside the machine on a published 127.0.0.1 port. Tried on Kiri, the better fit was VNC on the machine's own loopback, relayed through the engine: a port can't be added to a machine that is already running (the owner's is), a 127.0.0.1 port is no use to someone on another computer, and a viewer on the same computer could type into it. noVNC ships in the client instead (MPL-2.0, pinned to 1.4.0: 1.5 and 1.6 don't bundle).
- **A plain click uses a machine** (terminal and desktop), where every other card needs Ctrl-click. That is what "type into the VM when focused on the object" asks; the wheel still pans the grid until the card is in use.
- **XFCE**, not a bare window manager: about the same download (the X libraries dominate) and a desktop people recognise.
- **Every agent action is logged, looks included**, and screenshots are not kept in the archive (uploaded files are never deleted, so each look would stay for ever).
- **Notes and tables as wire ends** are a server-side reading of `LinkDoc` rather than new ports on notes and tables.
- **The script runtime** (tests only) gained a playbook for *use the desktop of “name”*.
